### The Thing with Python
See back in those days, people made a PC, then studied the asm based on that PC architecture. Then they wrote a whole compiler for it.

So each time, when a NEW pc came, new "asm" had to be studied, which was used to write the language on top.

HERE, I'm not doing that whatsoever. I'm supposed to create my own language using [vr-asm](/vr16-docs/assembler.html).

I used direct <span class="cb">ad64</span> python to write both my compiler and the assembler cause life is fun and easy with this lmao.

# What's the issue with the waveform?
No one asked but yeah.

I wrote a top-module named <span class="cb">vr16_cpu.v</span> and uh I connected everything. I edited the mem file to this:
```shell
0001000000000001
0001010000000010
0000100001xxxxxx
1111xxxxxxxxxxxx
```
In vr-asm this translates to:
```assembly
start:
    addi r0, 1;
    addi r1, 2;
    add r3, r0, r1;
    halt;
end:
```
Yet, the r3 waveform didn't store the value of 3. r2 had value 3. So there's some connection logic thats pending to be fixed.
